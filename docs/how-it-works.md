# Как это работает

[← README](../README.md) · **Русский** · [English](how-it-works.en.md)

Пять шагов, каждый можно запускать отдельно.

## Опись

Обход дерева облака. Для каждого файла в `catalog.db` пишется имя, размер,
дата, `md5`, `sha256` и место в дереве — **до** попытки скачать. Поэтому
запись остаётся даже у файла, который уже не отдаётся.

- Обход идёт с чекпоинтом: очередь папок лежит в базе, обрыв продолжается
  с того же места. «Начать заново» — галочка в «Инструментах».
- В конце описи включается сверка: файл, который был в прошлой описи и
  исчез из текущей, получает `vanished_at` и перестаёт считаться живым.
- Папки записываются отдельно от файлов: дерево строится по ним.

## Проба

Проверка доступности без скачивания. У хранилища запрашиваются **первый и
последний байт**: так видно не только «отвечает / не отвечает», но и «отдаёт
начало и обрывается на середине».

| Состояние | Что значит |
|---|---|
| `ok` | отдаёт оба байта |
| `unavailable` | отвечает ошибкой или обрывается |
| `gone` | `404` — файла нет |
| `api_error`, `unknown` | определить не удалось |

Результат живёт 12 часов (`PROBE_TTL_HOURS`). После этого «доступно» — это
воспоминание, и в интерфейсе оно помечается как устаревшее.

## Выгрузка

Файл пишется в `<имя>.part`, считается хеш, и только при совпадении с описью
файл переименовывается в настоящее имя. Что это даёт:

- оборванная загрузка остаётся `.part` и докачивается с места обрыва;
- несовпавший хеш не выдаётся за спасённый файл;
- если в описи хеша нет, копия помечается `unverified` — она на диске, но
  сверять её не с чем.

Режим «спасать с дырками» (`salvage`) читает файл блоками и пропускает
мёртвые участки: на выходе файл с дырками, помеченный `salvaged`. Часть
содержимого лучше, чем ничего, но такой файл не считается проверенным.

## Круг

Повторяет выгрузку, пока его не остановят.

- Очередь **пересобирается каждый проход**: спасённое выпадает само,
  исчезнувшее из облака тоже.
- Файл, провалившийся только что, откладывается на 20 минут
  (`LOOP_COOLDOWN_MIN`): за минуту больное хранилище не чинится.
- Свежий `404` пропускается и перепроверяется раз в сутки
  (`GONE_RECHECK_S`): это ответ API, а не больная машина.
- Полный диск останавливает режим: при свободном месте меньше запаса
  (`RESERVE`) выгрузка возвращает `no_space`.

## Архив

Упаковка спасённого в 7z. Настройки — в окне «Архив»:

- **размер тома**: 3.9 ГБ (премиум Телеграм), 1.9 ГБ (обычный), «не дробить»;
- **сжатие**: без (`-mx0`, быстро), обычное (`-mx5`), максимальное (`-mx9`);
- после упаковки каждый том проверяется по `sha256`.

Освобождение оригиналов (`released`) — отдельное действие: файлы остаются
в архиве, локальные копии убираются.

## Удаление из облака

Три уровня строгости:

| Уровень | Что удаляет |
|---|---|
| скачано | есть копия, хеш сошёлся |
| в архиве | файл упакован, архив проверен |
| мусор | по имени файла, даже без копии |

Перед запуском показывается, сколько файлов уйдёт и сколько заблокировано.
Удалённое записывается в `cloud_deleted`; опись об этом помнит.

## Интерфейс

- **Четыре кнопки** — опись, круг, архив, удаление. Число внутри — ответ на
  «сколько будет с этим выбором».
- **Линзы** «Сейчас / Было / На диске» меняют все числа разом: что облако
  держит, что было в описи, что лежит у вас.
- **Здоровье** — причины отказов, сведённые к понятным, узлы с отказами,
  задачи за неделю. Считается по базе, а не по логу.
- **Инструменты** — остальные действия: превью, проба, автопилот, узлы,
  учёт перенесённого, сверка зеркала, лог, настройки.
- **Вид** — масштаб (авто, 90–150%), плотность, тема, язык.

## Данные

Всё лежит в одной папке:

```
files/      зеркало облака, структура один в один
meta/       превью
archives/   тома 7z
logs/       журнал
catalog.db  опись, пробы, история, архивы, задачи
```

`catalog.db` — обычный SQLite: `resources`, `probe`, `probe_history`,
`local`, `cloud_deleted`, `archives`, `archive_volumes`, `jobs`.
