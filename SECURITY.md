# Безопасность

[← README](README.md)

## Сообщить о проблеме

Не открывайте публичный issue, если речь о доступе к данным. Напишите на
почту из профиля GitHub: что происходит, как воспроизвести, версия системы
(Windows, macOS или Linux) и Python. Логи — **без токенов и имён файлов**.

Ответ в течение недели.

## Что считается проблемой

- токен утёк в лог, в интерфейс или в отчёт об ошибке;
- удалён файл, у которого нет проверенной копии;
- имя файла или содержимое описи приводят к выполнению кода;
- файл считается спасённым, хотя хеш не совпал.

## Как хранится токен

Каждая система держит секрет своим механизмом:

| Система | Где лежит | Чем защищён |
|---|---|---|
| Windows | `%LOCALAPPDATA%\Drydock\credentials.bin` | DPAPI текущего пользователя |
| macOS | связка ключей, запись `Drydock`/`credentials` | Keychain |
| Linux | libsecret (`secret-tool`) | служба секретов системы |
| Linux без службы секретов | `~/.config/Drydock/credentials.json` | права 0600, без шифрования |

Скопировать хранилище на другую машину и расшифровать нельзя. Наружу уходят
только «токен есть/нет», название хранилища и хвост ClientID.

Переменная `DRYDOCK_SECRETS` переводит хранилище в обычный файл по
указанному пути — это режим для тестов и разовых запусков, шифрования в нём
нет.

## Что не присылать

Токены, Client secret, `credentials.bin`, скриншоты с реальными путями,
дампы `catalog.db` (там имена и структура коллекции). Если без этого не
обойтись — замените значения на `XXXX`.
